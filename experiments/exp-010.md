## Task

Before any side-effecting evaluation trust, run a **Criteria Adversary** against Ideal State Criteria produced by `generateCriteria` (and selected hand-written FAIL fixtures). The adversary attempts weasel language, unprobeable claims, and reward-hacking paths that satisfy literal criteria while violating intent. Measure game escapes **before vs after** one harden pass, and record benefit vs cost against pre-registered thresholds.

## Outer Binary Ideal State Criteria

1. **[outcome]** Adversary protocol is documented and produces a structured report per criteria set: `{ games_found, severity, exploit_sketch, harden_suggestion }`.
2. **[outcome]** On the four SAMPLE_IDEAS auto-criteria, high-severity game count after one harden pass is **strictly lower** than baseline (or baseline is already 0 and stays 0).
3. **[outcome]** Existing the reference engine unit contracts still pass (`npm test`): sample scores/verdicts, FAIL→KILL, anti-loop edges.
4. **[guardrail]** Adversary does **not** relax `checkCriteria` hard gate; FAIL criteria still force KILL on strong intake.
5. **[economic]** Adversary cost ≤ **1 extra model pass** (or equivalent scripted pass) per criteria set for the measured run.
6. **[guardrail]** No product topology change (no new pipeline stages, no self-mod graph); analysis + optional pure helper only.
7. **[outcome]** Benefit/cost decision is recorded: **keep / shadow / abandon** using thresholds below.

## Benefit / Cost Gate (pre-registered)

| Axis | Threshold |
|------|-----------|
| **Benefit** | ≥50% reduction in high-severity games on SAMPLE_IDEAS criteria **or** baseline high-severity = 0 with adversary confirming 0 |
| **Cost** | ≤1 extra pass per criteria set; wall-clock overhead documented |
| **Regression** | Zero failures on existing `engine.test.ts` contracts |
| **Ship rule** | Keep only if benefit met AND cost met AND no regression; else shadow or abandon |

## Golden Inputs

- `SAMPLE_IDEAS` (strong / vague / bleeding / iterate-band)
- `FAIL_CRITERIA` weasel fixture from `engine.test.ts`
- Optional: one hand-weakened criteria set (deliberately soft) as positive control for adversary detection

## Method (GXP loop)

1. **Brief freeze** — this file is the task brief.
2. **Baseline** — generate criteria for each sample; run adversary; count games by severity.
3. **Harden** — apply one structured harden pass (rewrite flagged criteria only).
4. **Retest** — adversary again; run `npm test`.
5. **Decide** — keep / shadow / abandon per gate; write Results.

### What was not changed (failures are data)

- `generateCriteria` still emits tautological intake embeds and the c5 `"or a concrete reframe exists"` escape. Not silently fixed.
- `checkCriteria` still only scores criterion *wording*, not idea-vs-criteria satisfaction. Not silently expanded into a new pipeline stage.

## Key Insight

`generateCriteria` writes **self-satisfying restatements** of intake (`"a real person-type is named: <whatever the founder typed>"`) plus a **pain escape hatch** (`"or a concrete reframe exists to raise it honestly"`). `checkCriteria` then PASSes on binary verbs + optional numerals. The criteria hard gate therefore does not reject vague or category avatars; it only rejects *malformed criterion prose*. Soft-close protection in today's engine lives in the dimension scorers (pain/POP), which is why vague still KILLs — not because ISC did its job.

One structured harden pass that **strips embeds, forbids category language, removes the OR-escape, and requires a named evidence source type** removes every scripted high-severity game (21 → 0, 100% ≥ 50% benefit) at **1 scripted pass per set**. Passing the hardened text into `evaluateIdea` does **not** change sample scores or verdicts, because `criteriaCheck.score` is still a wording score of 100. That is the limit of a text-only harden: it improves the *bar a later checker could use*; it does not, by itself, make the current engine apply that bar to intake.

**Circularity (recorded, not hidden):** the scripted detector and hardener are paired. 100% reduction is expected for the encoded patterns. Lead residual review of hardened text still sees medium-class leftovers the detector does not score as high: (1) architectural — `checkCriteria` never compares intake to criteria; (2) trivial thresholds still satisfy “auditable number + deadline”; (3) a named source type can be invented. Those are exp-019 (Red Queen) / exp-011 (genome) fuel, not a reason to relax this gate.

**KEEP scope:** keep the protocol + pure helper (`analyzeCriteria` / `hardenCriteria`) in the reference engine, **not wired** into `evaluateIdea` / `generateCriteria` this session. Wiring would be a topology change (forbidden) and would not move sample verdicts until a real idea-vs-criteria probe exists. exp-011 may version the hardened templates as genome defaults.
