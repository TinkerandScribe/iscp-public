# gxp-exp-019: Red Queen (Multi-Generation Adversary)

**Campaign:** [Criteria Evolution](CAMPAIGN-criteria-evolution.md) · Phase 2b · Evo-bio  
**Status:** Executed 2026-08-25 — **KEEP** (periodic Red Queen, not one-shot audit)  
**Depends on:** exp-010 adversary protocol + harden path  
**Clock:** τ4 across generations  
**Surface:** the reference engine criteria lineages

## Evolutionary hypothesis

**Red Queen:** Defenses and attackers co-evolve. A single harden pass can look sufficient while residual game surface remains; successive adversary generations find new escapes unless harden pressure continues. Escape rate over generations distinguishes “one-shot audit” from ongoing co-evolution need.

## Task

Run **G ≥ 3** generations:

1. Adversary finds games → harden (one class) → freeze genome  
2. Fresh adversary (new session / temperature / strategy notes) on hardened genome  
3. Repeat

Track high-severity escape count and novelty of exploit sketches each generation.

## Outer Binary Ideal State Criteria

1. **[outcome]** ≥3 generations completed with frozen intermediate genomes and reports.
2. **[outcome]** Each generation uses a **fresh** adversary attempt (not copy-paste of prior exploit list only)—protocol states how freshness is ensured.
3. **[outcome]** Metrics logged per generation: high-severity count, medium count, novel exploit rate (not seen in prior gen).
4. **[outcome]** Terminal decision rule pre-registered, e.g. stop when high-severity = 0 for two consecutive gens **or** G max hit.
5. **[guardrail]** Sample contracts still pass at every generation freeze.
6. **[economic]** ≤1 harden + 1 adversary pass per generation; G max ≤ 5.
7. **[guardrail]** No topology change; exp-010 cost discipline remains.

## Benefit / Cost Gate (pre-registered)

| Axis | Threshold |
|------|-----------|
| **Benefit** | Curve of escapes over G published; either stabilizes at 0 or shows ongoing novel escapes (both inform policy) |
| **Cost** | ≤5 generations |
| **Ship rule** | If novel high-severity continues after gen 2 → standing policy: periodic Red Queen re-run (not one-shot audit); if stable 0 → one-shot+spot-check acceptable |

## Method

1. Start from exp-010 baseline or post-harden genome.
2. Loop adversary → harden → test through G.
3. Plot/table escapes; decide policy.

## Out of Scope

- Live production traffic adversaries
- Automated continuous red team service

## Key Insight

exp-010's 21→0 looked like a finished war. Gen 2 immediately found a **high** residual the v0 detector cannot see: “weekly cost” without a numeral (the harden *template itself* is unprobeable). Gen 3 found a medium leftover: the prohibition phrase `wellness want` is a synonym hole. One-shot audit is the wrong policy. Standing rule: **re-run a fresh adversary pack after each harden epoch, and on a calendar (τ4) even if the last detector reports 0.**

Do not silently expand `analyzeCriteria` in product without a new experiment id (that would be a drive-by τ4). The gen 2/3 packs stay in `evo.test.ts` as fixtures.

**KEEP scope:** periodic Red Queen. Not a continuous red-team service.
