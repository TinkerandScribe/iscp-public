### Anti-loop verification
- `rewritePass: 0` on seed → ITERATE, `antiLoopApplied: false`
- `rewritePass: 1` → still ITERATE
- `rewritePass: MAX_REWRITE_PASSES (2)` → forced KILL + `antiLoopApplied: true`
- Strong pursueable ideas ignore the rewrite cap (correct)

### Hybrid Verification mapping
- **Outer hard gate**: `checkCriteria` (binary ISC, weasel rejection, 4–8 binding) + `decideVerdict` thresholds. FAIL criteria force KILL even on strong intake.
- **Inner refinement / test-time compute**: weighted dimension scorers (avatar, problem, pain hierarchy, POP, evidence honesty, offer clarity). These produce confidence signals before the outer acceptance decision.
- This structure already satisfies the Hybrid Verification Node pattern from gxp (outer owns Ideal State Criteria and side-effect permission; inner may refine).

### Experience Memory gap (Criterion 4)
Rejection patterns (weasel criteria, soft-close POP language, founder-as-customer bias, anti-loop force-kills) are computed and surfaced in notes/rationale, but are not yet written as hierarchical Experience Memory that persists across browser sessions or idea families. Local history store exists; a durable failure-class store would complete Criterion 4.

## Key Insight
the reference engine already realizes a clean Hybrid Verification Node under the four builder invariants. The outer GXP criteria gate is absolute, anti-loop is explicit and tested, and soft closes are rejected. The only material gap for full gxp alignment is durable hierarchical Experience Memory of rejection patterns. No uncontrolled mutation exists. Further topology self-modification is not required at this scale.

**Recommendation:** Treat current engine as the Hybrid baseline. Next incremental improvement (still inside invariants) is a small Experience Memory write path for rejection fingerprints that can be consulted on subsequent evaluations of related ideas.
