**Helper (pure, not wired):** `the reference engine/src/lib/the reference engine/genome.ts`

## Task

Treat Ideal State Criteria as a **versioned genome**: stable ids, tags, probeability metadata, and empirical fitness—not a disposable string list. Mutations (split, harden, demote hypothesis→guardrail, sunset) occur only from logged evidence. Measure whether genome discipline reduces silent criteria drift without exploding complexity.

## Outer Binary Ideal State Criteria

1. **[outcome]** Criterion schema includes at minimum: `id` (stable), `tag` (`outcome`|`guardrail`|`hypothesis`|`economic`|`negative`), `text`, `version`, `fitness` fields (`probe_reliability`, `false_pass_rate`, `game_escapes` or documented stubs).
2. **[outcome]** Ids **never renumber** once assigned in a session/genome lineage.
3. **[outcome]** Mutation log exists: each change cites evidence ref (adversary finding, test failure, or CI-EM placeholder id).
4. **[guardrail]** Core genome tags (binary probeability, no invented evidence, anti-loop related guardrails) are harder to mutate than peripheral domain text (documented rule).
5. **[outcome]** Existing evaluate path still satisfies sample contracts after schema adaptation (adapter allowed).
6. **[economic]** Schema + logging overhead does not add more than one durable write per evaluation in the prototype.
7. **[guardrail]** No topology self-modification; purifying default (no evidence → no mutation).

## Benefit / Cost Gate (pre-registered)

| Axis | Threshold |
|------|-----------|
| **Benefit** | 100% of criteria in prototype path carry stable ids + version; ≥1 evidence-gated mutation demonstrated end-to-end |
| **Cost** | ≤1 extra structured write per eval; no break of `npm test` sample contracts |
| **Ship rule** | Keep schema if benefit met; else abandon genome productization and keep flat criteria |

## Evolutionary constraints applied

- Purifying selection default
- Error-threshold: max one mutation class per run in this exp
- Core vs peripheral genome documented

## Method

1. Extend type/schema (the reference engine and/or `memory/experience_format.md` companion).
2. Map current `Criterion` → genome record without changing checker semantics.
3. Demonstrate one harden mutation with evidence citation (can reuse exp-010 finding).
4. Verify tests + document fitness stub update rules.

## Out of Scope

- Full CI-EM retrieval product (exp-012)
- Automatic mutation without evidence

### Fitness stub update rules

- `game_escapes` ← count of adversary games on that id after one `analyzeCriteria` pass.
- `probe_reliability` ← `1` if zero games else `0.4` (stub; not a calibrated probability).
- `false_pass_rate` remains `null` until a checker compares intake to criterion (architectural gap from exp-010).
- Stubs update only via `applyFitness` (one write). No silent overwrite during `evaluateIdea`.

## Key Insight

A versioned genome is cheap **if it is an adapter around the existing flat `Criterion`**, not a second checker. The valuable discipline is the **mutation log + purifying default + core lock**, not the fitness numbers (still stubs). Wiring genome into `generateCriteria` would be a τ4 product mutation and is not justified by this exp: sample verdicts do not move when hardened text is passed through `evaluateIdea`, because the engine still scores intake fields, not idea-vs-criteria satisfaction.

**KEEP scope:** keep `genome.ts` as the standing schema + mutation API. Do not auto-mutate. exp-016 may use `mutate` vs `mutateBatchUngated` as the error-threshold fixture.
