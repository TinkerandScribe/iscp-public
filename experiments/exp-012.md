# gxp-exp-012: Criterion-Indexed Experience Memory (CI-EM)

**Campaign:** [Criteria Evolution](CAMPAIGN-criteria-evolution.md) · Layer 3  
**Status:** Executed 2026-08-25 — **KEEP**  
**Depends on:** exp-011 stable criterion ids  
**Clock:** τ2 (session memory)  
**Surface:** the reference engine rejection paths + curriculum-forge `.ai/failures/` + `memory/experience_format.md`  
**Helper (pure, not wired):** `the reference engine/src/lib/the reference engine/ci-em.ts`

## Task

Write failures as **criterion-indexed** Experience Memory entries (not task-slug logs only). Retrieval for a later evaluation consults failures of *criteria classes like these* in *topologies like this*. Measure whether one held-out case benefits from reuse without contaminating an incompatible domain.

## Outer Binary Ideal State Criteria

1. **[outcome]** CI-EM record schema is specified and used for ≥5 real failure writes, including fields: `criterion_ids`, `mode`, `topology_context`, `resolution`, `transfer_scope` (`workflow`|`family`|`ecosystem`).
2. **[outcome]** Compatible with / extends gxp `memory/experience_format.md` (`failed_criteria` remains meaningful).
3. **[outcome]** At least **one** held-out the reference engine path shows correct reuse (same failure class avoided or flagged) when CI-EM is consulted.
4. **[guardrail]** At least **one** deliberate cross-domain probe (e.g. laser-safety failure → nature-study pack) is **quarantined** (not auto-applied); contamination attempt documented.
5. **[outcome]** Writes occur only after deterministic or high-confidence verification (GXP memory write rules).
6. **[economic]** Retrieval prototype may be grep/filter; cost of write+read documented; no requirement for vector DB.
7. **[guardrail]** No topology rewrite in this experiment—memory only.

## Benefit / Cost Gate (pre-registered)

| Axis | Threshold |
|------|-----------|
| **Benefit** | ≥1 true positive reuse on held-out case **and** ≥1 successful quarantine of incompatible transfer |
| **Cost** | Write path ≤ trivial structured append; retrieval latency acceptable for offline analysis |
| **Ship rule** | Keep CI-EM write format if benefit met; retrieval can stay minimal |

## Key Insight

Indexing failures by **criterion id + family + transfer_scope** is enough to get a true-positive reuse and a true-negative quarantine without embeddings. The load-bearing field is `transfer_scope: ecosystem` on laser: family-gated retrieval (`P1`) cannot see it, so a nature-study or idea-eval run cannot auto-apply equipment-specific safety knowledge. P0 (unrestricted) *does* contaminate — that is the anti-pattern exp-020 measures.

**KEEP scope:** keep the write format and in-process filter. Do not auto-inject retrieved failures into `evaluateIdea` or forge enrich (that would be topology). Retrieval policy measured in exp-020.

- Benefit: ≥1 TP reuse AND ≥1 quarantine → **pass**
- Cost: structured append + filter → **pass**
